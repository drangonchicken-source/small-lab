실험 기록

  • 03/04는 3월 4일인가 4월 3일인가
    날짜 형식을 명시하지 않으면 같은 문자열을 서로 다르게 해석할 수 있다.
  • 한쪽 표만 순회하면 추가된 행을 놓친다
    양쪽 키의 합집합으로 추가·삭제·변경을 따로 비교한다.
  • 참과 거짓이 숫자 검사에 통과하는 경우
    Python에서 bool은 int 하위형이다. 필요한 경우 정확한 자료형 조건을 정한다.
  • 주문번호만으로 중복을 지우면 상품이 사라진다
    한 행의 의미를 정한 뒤 필요한 복합 키로 중복을 검사한다.
  • CSV의 줄 수와 데이터 행 수가 다른 경우
    따옴표 안 개행은 같은 셀에 포함될 수 있어 파일 줄 수로 행 수를 세면 다르다.
  • CSV의 쉼표를 직접 나누면 열이 늘어나는 이유
    CSV의 따옴표 안 쉼표는 열 구분자가 아닐 수 있다. CSV 파서를 사용한다.
  • 날짜를 글자로 정렬하면 11월이 2월보다 앞선다
    날짜 자료형으로 해석한 후 정렬한다. 앱별 날짜 인식은 별도 확인한다.
  • 0.1 더하기 0.2를 그대로 비교하면
    이진 부동소수와 십진수 계산은 표현이 다르다. 목적에 맞는 오차·자료형 규칙을 사용한다.
  • 이름이 같다고 중복 삭제하면: 가상 고객 3명 비교
    서로 다른 고유번호의 동일한 이름을 하나로 합치면 실제로 다른 행을 잃는다. 중복 기준부터 정한다.
  • 열 이름이 같으면 앞 열을 잃을 수 있다
    Python DictReader에서 중복 헤더는 같은 키가 된다. 헤더 중복을 읽기 전에 검사한다.
  • 대문자 확장자 파일이 필터에서 빠지는 이유
    문자열 필터의 대소문자 규칙과 파일시스템 동작을 구분한다.
  • 파일 이름 정렬에서 10이 2보다 먼저 오는 이유
    문자열 비교와 숫자 비교는 서로 다른 순서를 만들 수 있다. 실제 앱의 정렬 방식은 앱별 확인이 필요하다.
  • 일치하는 행만 남기면 빠지는 항목
    내부 결합은 불일치 항목을 제외한다. 누락 목록을 별도로 보존한다.
  • 표 두 개를 합쳤는데 금액이 두 배가 된 이유
    일대다 결합은 원본 금액 행을 복제한다. 결합 전후 행 수와 집계 기준을 확인한다.
  • 상품코드 0012가 12로 바뀌는 순간: 숫자 변환 실험
    식별자를 정수로 변환하면 선행 0이 보존되지 않는다. 금액과 식별자의 자료형을 구분한다.
  • 빈칸을 0으로 바꾸기 전에 확인할 것
    미수집과 관측된 0은 다르다. 평균의 분모 정책을 먼저 정한다.
  • 초와 분을 그대로 더하면 시간이 틀린다
    단위를 통일하고 원래 단위도 기록한다.
  • 환불의 마이너스를 지우면 합계가 달라진다
    부호는 데이터 의미의 일부다. 절댓값 변환을 합계 정리에 무조건 적용하지 않는다.
  • 숫자를 문자열로 비교할 때 생기는 필터 차이
    크기 비교 전에 자료형을 확인한다.
  • 숫자 12와 글자 12를 대조하면
    식별자의 자료형을 맞추되 선행0 등 의미가 사라지지 않는지 먼저 확인한다.
  • 행별 반올림과 마지막 반올림은 같지 않다
    반올림 시점을 명시하고 같은 규칙으로 검산한다.
  • 천 단위 쉼표와 항목 구분을 혼동하면
    문자열의 역할과 지역별 숫자 표기 규칙을 구분한다.
  • 같은 순간인데 보고서 날짜가 하루 다른 이유
    일별 집계는 타임존을 통일한 뒤 날짜 경계를 정한다.
  • 빈 값 필터가 0까지 지우는 경우
    진릿값 필터와 결측값 필터는 다르다. 0을 실제 측정값으로 보존한다.
  • 같아 보이는 글자가 일치하지 않는 이유
    유니코드 표현이 다르면 같은 글자도 문자열 비교에서 다를 수 있다. 정규화가 필요한지 확인한다.
  • 첫 열 이름에 보이지 않는 문자가 붙는 경우
    UTF-8 BOM을 인식하는 디코딩으로 첫 헤더를 비교한다.
  • 성공률 두 개를 단순 평균하면 생기는 차이
    분모가 다른 비율은 전체 성공 수와 전체 시도 수로 가중해 집계한다.
  • 번호 뒤 공백 때문에 같은 항목이 나뉘는 경우
    앞뒤 공백이 의미 없는 식별자에서만 제거 규칙을 정하고 적용한다.
